# 給与の学び舎 — 2026年度版

給与計算を初級・中級・上級の難易度別に学べる演習アプリ。TanStack Start安定版 + React + TypeScript + Nitroで実装し、Vercel向けに構成しています。

## 起動

Node.js 24以上。

```sh
npm ci
npm run dev
```

http://localhost:3000 を開きます。

## 学習機能

- 2026年度版のオリジナル問題172問（知識102問・計算70問）。初級46問・中級72問・上級54問。知識問題は四肢択一、計算問題は数値入力、解説・計算式付き。
- 本番の出題形式を参考にした正誤問題60問（組合せ36問・誤りの単一選択24問）。6分野に各10問を収録し、すべての記述に○×と理由を掲載。ライブラリで「正誤」と検索できます。
- 正誤の組合せ・事例判断・資料照合のオリジナル問題24問を追加。うち16問は折りたたみ式の別資料（勤怠表・賃金規程・等級表・令和8年分税額表等）を開いて解く計算問題。ライブラリで「別資料」を検索すると抽出できます。
- 「知識＋計算」24問では、法定割増率・上限額・料率などを設問に提示せず、解説で確認します。
- 難易度（初級・中級・上級）、ジャンルと6分野の絞り込み、検索、ブックマーク。
- トップで個人の目標期日を設定。残り日数に応じて「できた／余裕」の上限を分け、既存の長すぎる復習予定も前倒し。
- FSRS-7（ts-fsrs）で問題ごとの記憶の安定度・難易度を更新。目標保持率90%、初期学習ステップ1分・10分、再学習10分、fuzz無効。
- 誤答は必ずAgain。正答時はAgain / Hard / Good / Easyの自己評価を反映し、各ボタンに次回間隔を表示。
- 期限到来順に復習問題を優先し、その後に未学習問題を出題。1回最大10問。期限前の問題はライブラリから任意に練習可能。
- 学習記録、正答率、7日間の回答数、連続学習、1日の目標。日付は日本時間。
- 演習画面から開ける四則演算のポップアップ電卓と途中計算・メモ。問題文をスクロールしながら利用でき、見出しをドラッグして移動・タップで前面切り替えが可能。電卓は小数・パーセント・クリア（C）・1文字削除・計算結果コピーに対応し、問題を移動するとメモ・電卓の表示内容は自動でクリアされます。
- localStorageにカード・回答履歴・ブックマーク・目標を保存。JSONバックアップの書き出し・検証付き復元。
- メイリオ優先のフォントと、装飾を抑えた演習中心の画面。スマホを優先し、通常画面の下部ナビ、演習中の集中表示、即時採点、タッチ操作用の大きな選択肢。

クラウド同期・ログイン・サーバーDBは未実装です。ブラウザのデータを消すと履歴が失われるため、設定からバックアップできます。FSRSの個人パラメータ最適化は未実装で、既定パラメータによる問題単位の間隔調整を行います。

## 2026年度の教材方針

法令基準日を **2026年9月1日** としています。公的情報の調査確認日は2026年11月1日。

通常の給与・賞与・社会保険・勤怠・労働法令を扱うオリジナル演習です。難易度は当サイト独自の分類で、特定の資格や試験の級を表しません。初級は基本用語と単純計算、中級は条件の判断と複数手順の計算、上級は例外・上限の判断と複数制度を組み合わせた総合演習です。年末調整の計算は現在収録していません。

料率・税額の条件は各問題または別資料に明記（「知識＋計算」は解答後の解説で確認）。2026年度の根拠と更新方法は [docs/content-policy.md](docs/content-policy.md) に記載しています。健康保険医療分は全国一律ではありません。

難易度は `src/data/difficulty-2026.json` で問題IDごとに管理し、`src/lib/difficulty.ts` から読み込みます。開発中は現在のデータ形式だけを扱い、互換性維持のための移行処理や旧形式の分岐は追加しません。設計変更に伴う学習履歴のリセットを許容します。

## 目標期日と復習間隔

目標期日未登録では通常のFSRSを使います。登録後はFSRSが計算した間隔に、当サイト独自の目標期日までの学習用の上限を適用します。

| 評価       | 上限（日数） | 目標期日までの残り時間に対する上限 |
| ---------- | ------------ | ---------------------------------- |
| もう一度   | 1日          | 1/8                                |
| 難しかった | 3日          | 1/8                                |
| できた     | 7日          | 1/5                                |
| 余裕       | 14日         | 1/3                                |

FSRS・日数上限・残り時間上限のうち最も短い間隔を使います。これはFSRS本体の記憶モデルを変更するものではありません。目標期日の0時（日本時間）を締切とし、当日以降は通常のFSRSに戻ります。明日以降の日付を登録でき、変更・解除は設定画面から行えます。

目標期日の登録・変更時とデータ読み込み時に既存カードを確認し、最後の回答日時と評価から長すぎる予定を前倒しします。すでに期限を迎えた問題を後ろに延ばさず、前倒しした結果が過去になればすぐ復習対象にします。目標期日の延期・解除でも既存予定を後ろに戻さず、以降の回答で新しい条件を反映します。

保存形式はversion 2（`kyuyo-study-v2`）です。開発段階の方針に従い、旧形式からの移行処理は用意していません。目標期日もバックアップに含みます。

## 保存データと公開時の保護

保存データの読込・検証に失敗した場合は、学習と自動保存を停止し、元データを書き出せる復旧画面を表示します。正常なバックアップの復元、または確認付きのリセットで再開します。元データの書き出しは修復用であり、そのまま復元できる保証はありません。

バックアップは読込前に8MiBまでに制限し、回答履歴は50,000件、カード・ブックマークは収録問題数まで検証します。復元時は許可した項目のみでデータを組み立て直します。回答履歴が上限に達した場合は追加記録を止め、バックアップとリセットを案内します。ブラウザの保存容量によっては、それより先に容量上限に達する場合があります。

`nitro.config.ts`でMIME判定・リファラー・未使用の端末権限・フレーム埋め込みを制御しています。`src/start.ts`のリクエストミドルウェアは毎回暗号学的乱数のnonceを生成し、CSPヘッダーとTanStack RouterのSSRに同じ値を渡します。ブラウザ側ではTanStackがnonceを引き継ぎます。本番の`script-src`はnonceと`strict-dynamic`を使い、`unsafe-inline`・`unsafe-eval`を許可しません。Analyticsは許可されたアプリのスクリプトから読み込まれ、計測通信は同一オリジンのみ許可します。CSSはReactが更新するグラフ・電卓のインラインスタイルを許可しています。

nonce付きHTMLの共有・再利用を避けるため、HTMLは`private, no-store`で返します。静的アセットの長期キャッシュは維持します。カスタムStartインスタンスでもサーバー関数のCSRF保護が継続するよう、明示的に標準のCSRFミドルウェアを登録しています。開発時だけViteのスクリプトとローカルWebSocket通信を許可し、本番ビルドには適用しません。

ローカルで`npm run dev`を起動してから`node scripts/security-browser-check.mjs`を実行すると、独立したブラウザで実際のヘッダー、復旧・容量制限・キャンセル・復元・リセットを確認します。事前に`NITRO_PRESET=vercel npm run build`を実行してください。Vercel向け出力にも静的なセキュリティヘッダーが含まれることを確認します。

本番CSPの検証は、ビルド後に`npm exec vite preview -- --host 127.0.0.1 --port 3002`を起動し、`node scripts/csp-browser-check.mjs`を実行します。nonceの応答ごとの更新・SSRとの一致・画面の起動・Analytics・電卓を確認し、不正に挿入したインラインスクリプト・同一オリジンの外部スクリプト・イベント属性・evalが拒否されることを検証します。公開サイトからAnalyticsの配信スクリプトのみを取得し、計測通信はすべてローカルで受け止めます。配信スクリプトを事前保存して`ANALYTICS_SCRIPT_FILE`で指定することもできます。

`TEST_BASE_URL=http://127.0.0.1:3002 node scripts/browser-check.mjs`と`TEST_BASE_URL=http://127.0.0.1:3002 node scripts/security-browser-check.mjs`で、本番ビルドに対して通常の演習とデータ保護も確認できます。本番デプロイのヘッダーはデプロイ後に別途確認が必要です。
